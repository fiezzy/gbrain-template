# gbrain-template

A template for standing up a searchable knowledge base over a specific
project's repositories — locally in about an hour, or on a server your team
queries over MCP.

Clone it, list the repos, run three scripts.

```bash
git clone <this-template> acme-brain && cd acme-brain
./scripts/init.sh          # name it, pick an embedder, list the repos
./scripts/bootstrap.sh     # install gbrain, create the DB, clone + register sources
./scripts/refresh.sh       # index
./scripts/verify.sh        # prove it actually works
./scripts/register-mcp.sh ~/work/acme-api ~/work/acme-web
```

After that, agents in those directories can ask questions across every indexed
repo, look up symbols in under 100ms, and write findings back for the next
session to find.

---

## What you get

A directory that **is** the knowledge base. One `rm -rf` removes it completely.

```
your-project-name-brain/
├── brain.conf              the only project-specific file — generated by init.sh
├── sources.manifest        id ⇥ git-url ⇥ branch ⇥ strategy
├── sparse-excludes         paths to keep out of the index
├── inbox/                  notes, git-versioned, the only writable source
├── scripts/                init · bootstrap · refresh · verify · serve · register-mcp
├── deploy/                 server mode: compose, TLS, per-person access
├── .github/workflows/      push the manifest → the server applies it
├── docs/                   SETUP · TRAPS · AGENT-POLICY · ARCHITECTURE
│
├── sources/   ┐
├── db/        ├─ gitignored: derived, rebuildable from git + the manifest
└── .gbrain/   ┘
```

Everything above the line is ~40 KB of text you commit. Everything below it is
a cache. The source of truth is always git.

## Several brains on one machine

Each brain exports `GBRAIN_HOME` pointing at its own directory, so gbrain reads
`<brain>/.gbrain` instead of the global `~/.gbrain`. Postgres gets a dedicated
cluster per brain on an auto-picked port. Nothing collides, nothing is shared
except the things that should be — the reranker model file and the reranker
process, which are stateless and cached under `~/.cache/gbrain/models`.

The one genuine exception: **gbrain itself installs globally**, so its version
is machine-wide. `brain.conf` records the version a brain expects and
`verify.sh` reports drift, but nothing enforces it.

## Local or server

|                | local                                                | server                                          |
| -------------- | ---------------------------------------------------- | ----------------------------------------------- |
| who uses it    | you                                                  | your team                                       |
| embedder       | Ollama, free, 2560d                                  | hosted, ~$1/full index, 1024–1536d              |
| vector index   | none — exact scan (2560d exceeds pgvector's ceiling) | HNSW                                            |
| transport      | MCP stdio                                            | MCP over HTTPS with OAuth 2.1                   |
| teammate setup | —                                                    | one `gbrain connect` command, nothing installed |
| cost           | €0                                                   | ~€6–16/month                                    |

Both modes are the same repository with different values in `brain.conf`. See
`[deploy/README.md](deploy/README.md)` for the server path, including per-person
read and write scoping.

The embedder choice is a **one-way door**: the vector width is baked into the
database schema, so changing it later means re-embedding everything.

## Requirements

Local: `bun`, `git`, `curl`, PostgreSQL 17 with pgvector, and — for the local
embedding profile — Ollama. `llama.cpp` if you want the reranker.
`bootstrap.sh` checks all of it before touching anything.

On macOS: `brew install bun git postgresql@17 pgvector llama.cpp` and
[Ollama](https://ollama.com).
